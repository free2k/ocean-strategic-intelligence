接入方法
从 MP2_RSS_LINK 的官方聚合 Feed 路径中取访问凭据，在服务器使用 Bearer 鉴权调用 Open API。
不将带凭据链接作为普通 RSS alias 保存，不把密钥返回前端、原文链接或日志。
公众号文章、X 长文独立分页读取；X 推文是独立开关，默认关闭，可在账号卡片启用。
公众号通过代表文章 URL 新增；取消远端订阅需页面确认。X 账号新增／取消在 Mp2RSS 控制台完成，再刷新本系统列表。
本地停用采集不会取消付费订阅；所有已入库历史文章保留。

发现 14 个账号：10 个公众号、4 个 X 账号。
首轮获取近 72 小时的 61 篇公众号资料，供应商均返回非空正文；不以此承诺每篇都等于源站完整全文。

10 篇通过主题规则且有正文的资料已投递智库，文档总数由 111 变为 121，自动加工已启动。
这些公众号资料为中文原文，无需再次翻译。提取和向量状态以任务完成后发布的结果为准。
X 长文接口目前为空；IEA 推文 API 只读样本可用，但没有擅自打开推文采集开关。

同步与处理
mp2rss-sync.timer 每分钟检查待执行任务；无手动任务时按数据库中的 30 分钟间隔采集。
UI 的“刷新远端订阅”和“同步”均写入持久任务，不依赖浏览器保持打开。
首次近 3 天，后续从上次成功时间向前回扫 7 天；每周核对供应商可提供的历史，以发现修订和补正文。没有固定篇数总量上限。
网络、限流及单源失败均保留已成功内容；单个任务最长 45 分钟，中断后由会话锁保护重放。
原文稳定 ID、内容哈希和版本表确保重复投递不新增副本。逐文事务写入原版库和 mp2rss.items；该表同时作为可重放的智库投递记录。
只将通过主题规则且有正文的资料送入智库；导入脚本按 URL／哈希幂等处理，随后复用现有 pipeline-worker 自动提取、证据处理及向量化。
worker 通过正常登录接口请求智库处理；忙碌时不并发启动，后续同步和智库综合任务继续读取未投递资料。
只读 source 列表与文章列表不透露凭据。暂停或远端取消后保留旧内容和来源身份。

常用检查
systemctl status mp2rss-sync.timer
systemctl show mp2rss-sync.service -p Result -p ExecMainStatus
journalctl -u mp2rss-sync.service -n 30
systemctl start mp2rss-sync.service
注意：无待执行任务且未到自动时间时，手动启动 service 会正常返回 idle。需要立即采集时先在页面点击同步。
停用：systemctl disable --now mp2rss-sync.timer；不要删除新来源关联的历史文章。
恢复旧 UI 前先停用新 timer，再恢复对应 .output 备份并重启 knowledge-base；数据库数据不随 UI 回滚删除。

范围与限制
新接入不会让供应商回溯其尚未收录的历史。空列表与故障分别显示。
X 转推、引用、线程与媒体保留原始结构，首期 AI 使用外层文本，不把内层作者言论拼接给外层账号；图片 OCR、视频转写和线程完整恢复不在本次范围。
API 无正文时保留待补正文，不能将摘要冒充全文；模板和主题规则仍可能误分，需在文章库复核。
加工成功不等于事实已人工核验，指标和关系须能够回到原文证据。
