# 模型成本修复 1—5 与现有功能影响

日期：2026-10-25（北京时间）。

> 后续状态：本地实现已于当天 16:36 发布到腾讯云，Batch 已开启。本文保留部署前的实现说明；线上结果见《腾讯云模型成本修复部署记录_2026-10-25.md》。

**本次已在本地代码中实现 5 项改造，并完成回归、阅读页交互验证和生产构建；尚未发布到腾讯云。线上进程、定时器、环境变量和 API Key 均未在本轮变更。** 因此，腾讯云目前仍按此前审计到的逻辑运行，本报告不能作为线上已经降费的证明。

本次没有发送真实付费模型请求，没有全量重跑历史文章，没有实现方案 6 的云端预算和自动／人工 Key 隔离。

## 1. 对用户最直接的影响

| 修复 | 已实现的行为 | 对现有功能的影响 |
| --- | --- | --- |
| **1. 修复异常重试** | 持久化延期时间；普通失败最多自动尝试 3 次；权限、额度等明确错误直接暂停；超时或提交结果不明确时保留回执，不盲目重发 | 正常成功任务继续处理。故障任务可能停在候选／暂停状态，需要核对后恢复，不再无限自动尝试 |
| **2. 持久缓存和减少重复处理** | 按接口、模型、提示词和输入内容复用结果；跨重启保留；翻译分段续跑；导入只自动分类本次真正新增的文章 | 重复操作通常更快、调用更少。重复相同内容会复用已生成结果；修改正文、模型或提示词后按新请求处理 |
| **3. 按任务选择模型** | 普通分类、翻译、摘要默认使用 `qwen3.7-flash`；问答、研究和重要事实抽取保留原质量模型 | 分类边界、译文措辞和摘要表达可能改变，需要真实业务样本评估。现有人工校准和已保存结果保留 |
| **4. 全文翻译和图片识别按需** | 新 PDF、超过 12,000 字符的长文默认只生成开头摘要；全文翻译和识图由阅读页按钮发起 | 原文继续可读。新长文不再保证已有中文全文；首次点击后需等待。新图片不再默认生成说明；旧译文和旧识别结果可继续使用 |
| **5. 后台接入文件式 Batch** | 持久排队、JSONL 提交、轮询、结果回收和回执核对已实现；默认关闭 | 启用后，适用后台任务不再立即完成，可能等待最长 24 小时，再叠加后续流水线调度时间；人工问答和按需阅读操作仍走实时接口 |

**不能保证“所有体验完全相同”。** 主要变化是新全文／图像说明的生成时机、后台结果时效、故障恢复方式，以及便宜模型的输出差异。

## 2. 为什么这样改：对应过去 7 天的证据

统计口径沿用此前只读审计：2026-10-18 至 10-24 的 7 个完整北京时间自然日。

- 已保存的模型译文有 1,182 个版本，其中 PDF 的中文正文约 799 万字符，占这批译文字符的 **86.8%**。因此，减少默认整本翻译是最明确的业务范围优化。
- 一条短链进入模型阶段 1,698 次，涉及 192 次执行且全部延期。修复延期持久化和重复调度，可以直接处理这个异常入口。
- 语义任务完成 3,160 条，语义缓存新增 3,127 条，使用的是 `qwen-plus`；这部分适合评估便宜分类模型。
- 同期公网日志只看到 10 个不同资料 ID 的成功详细阅读，支持评估按需生成，但不能据此认定其它资料没有内部研究用途。

86.8% 是译文字符占比；1,698 是模型阶段事件数，二者都不是收费 token 或费用占比。当前没有覆盖全部请求的账单和 token 明细，不能承诺全账单降低某个固定百分比。各修复之间存在重叠，收益不能直接相加。

审计原文见同目录的《近7天模型消耗与降本优先级分析_2026-10-25.md》和《腾讯云部署与大模型调用费用审计_2026-10-25.md》。

## 3. 修复 1：失败和延期都进入持久状态

### 3.1 自动处理规则

| 情况 | 新处理方式 |
| --- | --- |
| 本轮时间不足，尚未开始实际请求 | 保存 `BATCH_DEFERRED`，推迟约 1 小时；不增加实际失败次数 |
| 已入 Batch 队列，或同一请求正由其它进程处理 | 保存等待状态，约 5 分钟后检查；不重复提交，不增加失败次数 |
| 普通临时失败 | 第一次失败后退避约 1 小时，第二次约 2 小时，达到第 3 次后暂停 |
| 400／401／402／403／404 或明确权限、欠费、免费额度限制错误 | 直接暂停，避免持续触发同一个错误 |
| 超时、连接中断、进程中断，无法确认服务端是否已经执行 | 标记 `uncertain`，停止自动重发，等待核对 |
| Batch 提交成功与否不明确、完成结果缺行、成功响应无法使用 | 保留不确定回执，不自动切回实时接口补发 |

证据链接失败状态会同时更新 `next_check`，修复原先延期后仍立即到期的问题。历史语义队列中已经失败且尝试次数达到上限的项目，会在新 worker 执行时转为暂停。

OpenAI SDK 的隐式重试关闭，避免 SDK 重试叠加业务层重试。人工交互失败仍会返回错误供用户判断；本次没有给所有人工接口增加自动重试。

### 3.2 功能代价

永久性错误和不确定请求不再“等它自己一直重试”。其原文、候选结果和已保存片段保留，但新 AI 结果可能缺失。修复密钥权限、额度或上游故障后，需要有针对性地恢复任务。

这不是人民币额度封顶：其它不同的新任务仍可能正常调用并产生费用。

## 4. 修复 2：缓存和处理范围

新增 `model_ops` PostgreSQL schema，保存模型请求回执、Batch 记录和按需生成任务。语义队列增加 `receipt_id`，便于从业务任务找到对应模型回执。

请求指纹包含服务接口、模型、完整请求参数及成本策略版本。同一请求并发到达时只允许一个执行者，成功响应跨进程和重启复用。已完成请求会清除重复保存的请求正文，保留结果和用量信息。

证据翻译继续兼容已有分段缓存，并新增与 URL 无关的内容指纹；相同标题、正文、模型的内容可跨 URL 复用。新的统一请求缓存还会核对具体提示词和参数。已有历史完整译文不因默认模型变化被强制重新翻译。

导入接口修正了两处行为：重复文章会计入跳过数；勾选自动分类时只处理本次真正插入且仍待分类的文章，避免导入一小批文章时扫描全部历史待分类库。

功能影响：

- 相同输入通常返回已保存结果，不会每次生成不同版本。
- 新正文、新模型或新提示词会生成新的缓存指纹。
- 缓存依赖数据库可用性和建表权限；数据库不可用时受管理的请求会失败，不会绕过缓存直接扣费。
- 按需结果缓存读取失败时，阅读接口回退到已有资料，暂时关闭生成入口；原文和已入库译文仍可查看。
- 本次未清理历史缓存，也未全量重分类历史数据。

## 5. 修复 3：实际模型分工

| 工作 | 新代码默认模型／方式 |
| --- | --- |
| 规则无法确定后的语义复核、普通文章分类 | `qwen3.7-flash` |
| 普通中文翻译、证据摘录翻译 | `qwen3.7-flash` |
| 长文开头摘要、文章导出摘要 | `qwen3.7-flash` |
| 研究问答、周期简报、重要结构化事实抽取 | 保留配置的 `CHAT_MODEL`，当前为 `qwen-plus` |
| 图片识别 | 保留 `MP2_VISION_MODEL`，当前为 `qwen3-vl-plus`；默认按需 |
| 向量 | 保留 `text-embedding-v4` 和原有各入口维度，不重建旧向量 |

通过 `INTEL_MODEL_CLASSIFICATION`、`INTEL_MODEL_TRANSLATION`、`INTEL_MODEL_SUMMARY` 分别覆盖模型；也可以将其中一类恢复到 `qwen-plus`。代码没有直接全局替换 `CHAT_MODEL`。

这一改造覆盖普通分类、翻译、摘要的主要路径。部分采集时一次性完成的抽取、研究模块和显式传入模型客户端的处理路径继续按原配置运行，不代表全系统所有文本调用都已切换到 Flash 或 Batch。

已经保留 JSON、引用来源、日期、数字和向量等既有校验。**测试使用模拟模型响应，没有做真实 `qwen3.7-flash` 与 Plus 的质量对照，也没有验证当前云端 Key 对新模型的访问权限。** 因而不能声称分类准确率和译文质量已经证明相同。

## 6. 修复 4：长文与图片的阅读流程

### 6.1 新 PDF／长文

默认规则为 PDF 或正文超过 12,000 字符时：

1. 保留原始完整正文、来源、采集快照和现有结构化处理能力。
2. 自动从原文前 5,000 字符生成中文标题和不超过约 300 字的摘要，限制输出为 700 token。
3. 摘录不完整时，摘要明确加上“以下摘要仅基于原文开头摘录”，不冒充整份报告总结。
4. 阅读页显示“生成中文全文”。只有点击才创建任务；刷新、打开、关闭文章均不会自动创建新的付费请求。
5. 后台按片段生成全文并保存进度。关闭窗口后任务继续保留；重新打开会查询原任务，完成后显示译文。

中文原文和已有完整译文保留。短网页文章仍按正常自动翻译路径处理。也可以用 `INTEL_TRANSLATION_MODE=full` 恢复原来的默认全文策略，但会恢复相应自动消耗。

重要影响：短摘要只覆盖开头，可能遗漏报告后面的结论、表格和章节；它不能替代完整阅读。本次没有实现章节选择、目录提取或只翻译相关页的 UI。用户请求全文时仍会产生相应费用，只是避免在尚未需要时预先生成。

### 6.2 新图片

默认下载并保存原始图片，停止自动识图。已有识别结果继续展示。资料存在已校验的本地快照时，阅读页提供“识别这张图片”；识别前检查快照路径、SHA-256、文件类型和大小。

识别结果保持候选证据属性，不根据曲线位置估算数值，不自动形成实际时间序列。新图片未被请求识别之前，其中文说明、可见文字和由此辅助的图像检索信息不会提前出现。

### 6.3 首次等待

按需生成使用实时模型接口，由独立后台 worker 执行，避免长 PDF 卡住 HTTP 请求。worker 每轮处理一个按需任务，大报告可分多轮续跑；排队、文档长度和模型响应都会影响等待时间，不能保证点击后立即完成。

按钮依赖 `INTEL_MODEL_WORKER_ENABLED=true`、AI 可用和数据库配置。应与 worker 一起部署和启用；当前本地模板默认关闭，避免显示无人消费的生成入口。

## 7. 修复 5：Batch 的范围与限制

已实现文件式异步流程：

`业务生成请求 → 持久队列 → 同模型／同接口 JSONL → 上传文件 → 创建 Batch → 保存云端回执 → 轮询并校验结果 → 业务下轮复用结果`

当前主要用于可重复进入、可恢复的自动语义复核、证据处理、补充翻译／向量和自动事实抽取路径。单批最多选取 50 条，限制 JSONL 大小；不同工作空间接口不会混投。人工问答、人工请求的全文和识图保持实时。

提交前先保存本地批次，避免崩溃后盲目再提交。明确失败按重试策略处理；无法确认执行情况时暂停核对。不确定的 Batch 可以在核对云端已有批次后绑定回执，随后继续回收，不能凭“本地没结果”再发一遍。

**Batch 默认未开启。** 开启需要显式设置 `INTEL_BATCH_ENABLED=true` 和 `OPENAI_BATCH_BASE_URL`，并确认该工作空间、模型、Key 支持文件式 Batch；可用 `OPENAI_BATCH_API_KEY` 指定对应 Key。代码不会因工作空间接口不支持，就擅自改投公共接口。

文件式 Batch 的折扣按符合条件的原价任务计算，且**不能抵扣新人免费额度**；如果实时任务还在使用免费额度，切换可能增加现金支出。当前没有查到完整账单或剩余额度，本轮没有在真实云端创建 Batch。[阿里云 Batch 文档](https://help.aliyun.com/zh/model-studio/batch-inference)、[免费额度规则](https://help.aliyun.com/zh/model-studio/new-free-quota/)

Batch 完成窗口为 24 小时，结果回收后还要等业务流水线再次处理。多片段任务若逐段进入队列，等待可能跨多轮；不能将“24 小时”视作整份长报告的总耗时承诺。本次未修改现有采集、交付和语义定时器频率。

## 10. 腾讯云上线时必须衔接的内容

以下是发布步骤说明，本轮没有执行。

### 10.1 发布完整代码与初始化

当前线上采集 worker 与情报服务指向不同发布目录，需要同时包含新增共用模块及各自的调用方变更。不能只替换一个 `server.mjs` 或只更新根目录，遗漏实际由 PM2／systemd 运行的 release。

主要变更文件：

- `intelligence/model-policy.mjs`、`model-retry.mjs`：模型分工与退避策略。
- `intelligence/model-request-store.mjs`、`model-client.mjs`：统一回执和持久缓存。
- `intelligence/model-batch-worker.mjs`：Batch 提交与回收。
- `intelligence/model-resources.mjs`、`model-resource-routes.mjs`：按需翻译／识图。
- `scripts/model-operations-worker.mjs`、`model-operations-admin.mjs`：后台执行和人工恢复。
- 现有证据、语义、补充处理、导入、导出、服务端和阅读页调用方。
- `deploy/independent-workers/model-operations.service`、`.timer`：新增后台服务模板。

先在实际 worker 发布目录执行 schema 初始化，仅建表，不发模型请求：

```sh
node --env-file=/opt/knowledge-base/.env scripts/model-operations-worker.mjs --init
```

语义 worker 启动时会为既有队列补充 `receipt_id` 字段。应确认执行账户有相应 schema／ALTER 权限。

### 10.2 同步有效环境变量

```dotenv
INTEL_MODEL_CLASSIFICATION=qwen3.7-flash
INTEL_MODEL_TRANSLATION=qwen3.7-flash
INTEL_MODEL_SUMMARY=qwen3.7-flash
INTEL_TRANSLATION_MODE=on_demand
INTEL_AUTO_VISION=false
INTEL_MODEL_WORKER_ENABLED=true
INTEL_BATCH_ENABLED=false
```

`INTEL_ENABLE_AI` 与现有 Key 按原授权保留。`INTEL_MODEL_WORKER_ENABLED=true` 应在后台服务安装可用后启用。

缓存使用的主数据库连接优先级为 `INTEL_AUDIT_DATABASE_URL`、`DATABASE_URL`、`INTEL_DATABASE_URL`、`NUXT_DATABASE_URL`；各进程应指向预期的共享缓存数据库。Nuxt 入口复用其现有数据库连接。按需全文向上游证据库回写，需要该缓存连接能够访问 `mp2rss` 表；没有这些表时仍可通过独立结果缓存显示，无法执行上游证据回写。

需要核对主 `.env`、`mp2rss.env`、`processing.env` 和 PM2 已保存环境的覆盖关系，保证所有实际运行进程拿到同一套策略。重启 PM2 时应同步更新有效环境，不能只编辑文件后认定已生效。

在确认真实 Batch 支持与计费条件后，再配置显式 Batch 接口及对应 Key，开启 `INTEL_BATCH_ENABLED`。真实 Key 不应写进本报告或仓库。

### 10.3 安装新增后台服务

提供的 unit 使用现有采集发布目录 `/opt/knowledge-base/mp2rss-current`。发布时需要按实际目录、Node 路径、数据库和图片目录核对，再安装并启用 timer。该 worker 在上轮结束约 1 分钟后运行，负责 Batch 回收和用户请求的资源生成。

不能只开启按钮而不启动 worker。也不应为了加快回收而随意提高所有既有采集／交付任务频率，避免引入额外工作量。

### 10.4 查看与恢复

以下管理动作本身不提交新模型推理；恢复后相应后台任务可能再次执行：

```sh
node --env-file=/opt/knowledge-base/.env scripts/model-operations-worker.mjs --status
node --env-file=/opt/knowledge-base/.env scripts/model-operations-admin.mjs --list-paused
node --env-file=/opt/knowledge-base/.env scripts/model-operations-admin.mjs --retry-request REQUEST_ID
node --env-file=/opt/knowledge-base/.env scripts/model-operations-admin.mjs --retry-resource RESOURCE_ID
node --env-file=/opt/knowledge-base/.env scripts/model-operations-admin.mjs --retry-semantic ARTICLE_ID
node --env-file=/opt/knowledge-base/.env scripts/model-operations-admin.mjs --retry-evidence 'https://example.org/original-link'
```

`uncertain` 请求会拒绝直接恢复。对于已在云端找到的对应 Batch，可用 `--attach-batch LOCAL_BATCH_ID PROVIDER_BATCH_ID` 核对 metadata 和输入文件后绑定回执，继续回收已有结果。其它不确定请求需要先核对提供商记录，本次没有自动重发它们的接口。

文件快照中的抽取／补充处理暂停状态，需要同时核对其业务检查点；仅恢复通用模型回执不会自动重置所有上层业务状态。本次未新增一键恢复全部故障的操作。

### 10.5 回退

可分别将分类／翻译／摘要模型恢复为 Plus，设置 `INTEL_TRANSLATION_MODE=full`、`INTEL_AUTO_VISION=true` 恢复对应自动行为，但费用会随之恢复。保留新增缓存和回执表，不通过删表回退。

关闭 Batch 不会取消云端已经接受的批次；仍需回收和核对这些回执，避免重新实时生成同一批结果。若整体回退旧代码，原先无限重试等风险也可能恢复，应保留止损修复。

## 11. 验收结论

本地已交付 1—5 的可运行实现与服务模板，主要降本方向是：减少默认长输出、复用已完成请求、对普通文本任务使用便宜模型，以及阻断失败后的重复请求。Batch 提供进一步优化渠道，需要单独验证、配置和启用。

腾讯云生产目前尚未获得这些修复；实际降费应在发布后，按同等业务量比较真实账单、模型 token、暂停队列与全文／识图请求量，不能用本地测试通过替代线上成本验证。
