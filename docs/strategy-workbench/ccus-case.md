# 北方之光研究展示案例

案例：北方之光：跨境 CO₂ 运输封存与投运时序。

访问：<http://49.233.77.111/ocean-intelligence/#research>。打开「工作台总览」中的「从研究问题开始查看预填案例」；已在案例全景内时可点击「查看已预填的完整研究流程」；也可在「智能选题推荐 → 长期跟踪研究主题库」搜索「海上CCUS」，从原主题卡片进入。

## 内容与录屏路径

| 模块 | 已提供的案例内容 | 可展示的操作 |
|---|---|---|
| 工作台总览 | 案例全景、事实底稿、路线、规模情景、条件性投资结果、参数说明与来源脚注 | 从一个真实研究问题进入，先区分事实、计划和研究设定 |
| 智能选题推荐 | 原 TH08 主题上的已计算案例入口 | 从推荐选题进入案例；完整优化主题仍保留补数与引擎要求 |
| 战略量化研究 | 源汇证据关系、合同规模情景与条件性 NPV 的真实计算档案 | 查看结果；恢复输入；核定参数和方法后另存新版本 |
| 战略研究方法库 | 本案例采用的方法、采用理由与能力边界 | 对照关系分析、单因素情景和现金流 NPV 的用途 |
| 研究成果管理 | 不可变版本、父子关系、输入与配置差异、原算法重现及导出 | 查看资金成本版本与收入延后版本相对于基准的差异 |
| 循证研究问答 | 已保存的案例整理答复、原始证据与冻结计算引用，以及可继续追问的问题 | 在原问答区域直接展示已保存答复，查看历史、来源并导出 TXT；整理答复明确标为非 AI 生成，继续追问仍使用原问答功能 |

适合的讲解主线：从已入库的官方协议出发，查看证据与数据性质，沿计划路线识别共享接收环节，再检验合同规模兑现、资金成本与收入延后的条件性影响，最后回到冻结版本和来源核对。

## 数据与方法口径

事实底稿来自网站现有数据库中的 Northern Lights 官方原文，发布时核对了资料标识、来源 URL、发布日期、关键原文片段及完整正文指纹。瑞典路线和启动窗口保留协议计划、附条件性质；扩建能力保留未来计划性质；Veas 的运行事件与瑞典协议分列。[¹](https://norlights.com/news/northern-lights-signs-agreement-with-oresundskraft-for-co2-transport-and-storage-from-sweden/) [²](https://norlights.com/news/northern-lights-phase-2-expanding-europes-co%e2%82%82-storage-capacity/) [³](https://norlights.com/news/northern-lights-has-injected-first-co%e2%82%82-from-wastewater/)

规模兑现比例、附属接收环节初始投资、单位净现金贡献、折现率、观察期和收入延后均为明确标注的研究设定，不来自真实工程估算、商业报价或项目财报。财务情景不是 Northern Lights 或 Öresundskraft 的项目估值。全部输入、参数依据及计算结果均保存在普通研究版本中，可从案例脚注下载核查。[⁴](http://49.233.77.111/ocean-intelligence/api/strategy/cases/northern-lights-ccus)

案例调用原有度中心性、确定性单因素情景和 NPV 引擎；没有接入或假称实现 GIS 源汇匹配、最优路径、MILP 多周期投资优化、完整 TEA 或 LCA。未把能力或封存量换算成净减排量。

## 发布和维护

程序读取 `INTEL_DATA_DIR/strategy-cases/northern-lights-ccus.json`，仅引用 `strategy-research` 中已计算并保存的不可变版本。案例源底稿与输入生成逻辑在 `intelligence/strategy/specs/cases/northern-lights-ccus.json`、`intelligence/strategy/case-inputs.mjs`；发布工具使用现有方法确认、输入核验与研究保存 API，不直接编造研究记录，也不修改文章、指标或官方序列。

原文变化或缺失时，案例显示待重新核对，冻结的研究版本仍保留。未来替换工程数据时须另建并核定版本，不能直接覆盖历史结果。完整流程修订在原生表单预填研究问题、对象范围、证据底稿、现金流、方法理由和参数，并在不可变版本中保存研究发现、局限与后续补数说明。案例整理答复写入现有研究问答记录，按固定 ID 引用，避免被近期历史条数限制遗漏。修改输入会撤下旧版本的预填研判，后续需重新核定。

浏览器验收覆盖原生四步、人工方法确认与输入核验、成果管理、问答引用和 TXT 导出、刷新恢复和移动端；验收未额外保存研究计算或调用模型。
