# 量化分析工作台：视频演示顺序与预填复核

复核日期：2026-10-18。依据当前案例配置、生成请求、前端交互和固定版本计算程序复算。本文为展示建议与审查结论，不代表已完成下述建议修改。

## 主线：一个研究问题怎样形成可追溯成果

建议以“海洋低碳：CO₂ 运输接入方案综合评价”走完流程，再用“海上 CCUS 源汇匹配与投资时序”补充经济性和时序检验。两者用同一业务背景，分别回答方案权衡与投资情景问题。不能说两个案例已经自动串联计算，也不能把运输接入方案比较说成所有海洋低碳技术路线的全面评价。

建议开场口播：

> 面对一条已经披露的跨境 CO₂ 服务链条，研究者关心的不只是有哪些信息，还包括不同接入方案如何权衡、结论依赖哪些假设，以及怎样保存证据和计算过程供后续更新。下面以库内公开资料为背景，用明确标注的研究情景走完这个过程。

## 综合评价主线的点击顺序

| 顺序 | 当前页面操作 | 展示重点与口播逻辑 |
| --- | --- | --- |
| 1 | 量化分析工作台 → 智能选题推荐 → 数据驱动选题 → 搜索“海洋低碳” | 选题由已有资料线索进入。展示原选题仍提示需补数据，说明有资料线索并不等于有完整计算矩阵。 |
| 2 | 在“海洋低碳：技术路线／项目综合评价”卡片点击“查看已预填的综合评价研究” | 从大方向收敛为具体问题：同一 CO₂ 接入服务目标下，怎样权衡共享运力、专用运力和分阶段租赁。 |
| 3 | “研究问题与边界”页 | 展示任务为综合评价、领域和国家范围、资料日期、对象总体、系统边界。解释这里比较的是运输接入设计；资料日期与未来情景期间分别记录。不要逐个朗读所有下拉框。 |
| 4 | 点击“下一步：指标与证据核定” → 查看矩阵 → 打开一个单元格的来源 | 展示成本、投入、准备期、能力、运输排放等维度。明确矩阵是研究情景；官方来源支持背景，不是企业报价原表。打开“库内原文”或脚注，完成一次证据追溯即可。 |
| 5 | 关闭来源框 → “下一步：方法匹配与参数” | 展示已保存的人工方法确认、熵权 TOPSIS、指标方向和扫描配置。解释先说明研究问题、数据性质和比较口径，再选方法。当前是已保存方法记录，不能讲成现场 AI 自动推荐。 |
| 6 | “下一步：结果检验与研判” → 下方已保存结果 | 按“排序 → 权重及标准化 → 同权方法对照 → 敏感性 → 研判及待补数据”顺序展示。先说“在本矩阵下”的条件性结论，再解释其边界。 |
| 7 | 点击“追加投入加快准备情景” → 展示“与父版本的差异” | 展示同一研究如何修订输入、保留旧版并核对差异。投入、准备期同时变化，归一化和熵权也重算；不能讲成单独识别了工期的因果作用。 |
| 8 | 点击“等权 WSM 交叉评价” | 展示改变赋权和评分规则后复核结论。它是独立方法研究；得分尺度不同，不直接相减。当前该任务的说明和局部敏感性标签存在待修问题，见下表。 |
| 9 | 顶部“研究成果管理” → 选相应版本“查看结果与来源” → 展示导出入口 | 说明成果不仅是一张排名图，还包括研究问题、冻结输入、参数、来源、算法及版本关系。录屏不必展开所有哈希值。 |
| 10 | 顶部“循证研究问答” → 点击已保存答复 → 点击一个上标引用 → “预览／下载 TXT 简报” | 先展示“哪些是事实、哪些是假设”，再展示“排序说明什么”。已有答复是案例研究整理，不能讲成现场 AI 生成。若录现场提问，应实际点击生成并等待真实结果。 |

查看已有计算结果时无需反复点击“计算并保存”。如果要展示一次真实计算，应单独录制：第三步“确认当前方法，用于新版本计算” → 核对冻结确认项 → “核验输入与方法前提” → 第四步“计算并保存研究版本” → 查看新版本。此操作会实际新增保存版本。硬约束提示语修正前，不宜把当前确认项讲成实际工程审核已经通过。

## 第一个 CCUS 案例怎样补充

入口：智能选题推荐 → 长期跟踪研究主题库 → “海上 CCUS 源汇匹配与投资时序” → “打开已计算的研究案例”。

该入口当前默认进入附属环节 NPV 的预填研究，而不是从源汇图开始。因此录制时先点“返回案例全景”，展示官方证据、计划与已发生事件的区别、源到汇关系，再进入“从研究问题开始”的投资情景流程。

推荐顺序：

1. 案例全景：从原文定位源、港口、接收站与封存环节，区分计划链条和已披露运行试点。
2. 源汇证据链：只说明已披露关系，不把连接度排序讲成最优源汇匹配。
3. 合同规模兑现情景：说明这是对协议上限的情景检验，不是实际服务量或预测。
4. 附属环节投资基准：展示现金流、折现率依据与 NPV。
5. 资金成本压力版本：现金流不变，改变折现率，查看版本差异。
6. 收入延后版本：保持既定初始支出，延后收入，说明时间价值风险。
7. 成果管理与问答只简短回扣主线，避免两个案例重复介绍所有按钮。

这几个任务属于同一问题背景下的局部研究，规模情景不会自动传入 NPV，证据关系也没有驱动运输路径优化。当前已明确这一限制，口播应保持一致。

## 预填复核结论

| 项目 | 判断 | 处理建议 |
| --- | --- | --- |
| 综合评价任务、海洋低碳领域、挪威／瑞典范围、人工核定矩阵入口 | 与本案例内容匹配 | 保留。不能改说为直接调用了一张库内真实工程成本矩阵。 |
| 成本／投入／准备期／排放为越小越优 | 与所声明比较意图一致 | 保留其限定范围；运输排放不能代替全生命周期净减排。 |
| 资料时点与未来情景期间分别声明 | 合理 | 录屏解释一次即可，不将资料日期当作运行统计期。 |
| 事实、计划、假设和计算结果分别标注；保存原文与冻结版本 | 合理 | 作为演示核心，而不是略过。 |
| 熵权 TOPSIS 作为主任务 | 可用于研究方法展示；不足以声称得到真实项目客观最优解 | 矩阵完全是情景设定，熵权仍由这些设定决定。面向非专业观众可先解释等权对照，再讲熵权；不为演示效果调数造排名。 |
| 年服务保障能力设置为持续“越大越优” | 研究取向尚需说清 | 若目标是固定服务需求，超过需求的能力是否额外得分需要依据；若目标还包含扩容或冗余，应明确写进问题。不能擅自改成饱和评分或删指标。 |
| 功能单位填成“相对综合得分，无量纲” | 输出尺度与服务功能混在一起 | 应将功能单位写成同一服务需求、期间与交付边界；另列“结果为无量纲相对得分”。这是边界表述完善，不是单位自动换算。 |
| 币值基年仅填“自设统一不变欧元” | 避免冒充工程造价，但未明确基年 | 若保留金额比较，应明确研究假设所用币值年份；当前未采用真实价格转换，不能口播为已按实际物价平减。 |
| 预填“核验通过”和硬约束已确认 | 情景数值筛选与页面工程审核文字不一致，正式录制前应修正 | 当前仅检查情景能力和准备期，实际许可、安全和可用运力未核验。应分别显示“情景数值约束满足”与“实际工程条件待核验”。不能只取消确认使案例无法运行，也不能保留容易误解的全面通过状态。 |
| 单元格“来源已核定” | 正文注明情景，但短标签容易被理解成真实数值有来源 | 展示案例应区分“情景设定已复核”与“真实原值已核对”。 |
| 等权 WSM 研判出现“熵权反映……” | 确认存在复用文案错误 | `evaluation-case-inputs.mjs` 为所有任务使用同一段研判，应按实际赋权方式分别生成。保存新版研判，保留旧版本。 |
| 等权 WSM 的逐项局部敏感性 | 确认存在计算方法与展示归属不一致 | 当前引擎局部权重扰动固定使用 TOPSIS；该任务主排序和九点扫描则使用 WSM。应让局部敏感性跟随所选评分方法，或明确改名为 TOPSIS 补充检验。修复时必须保留旧算法供历史重现。 |
| “核验输入与方法前提（含 AHP 一致性）” | 对当前熵权／等权任务不够准确 | 提示应根据方法显示；当前任务没有 AHP 判断矩阵，不应讲成通过 AHP 一致性检验。 |
| 参数调整版本同时改投入和准备期 | 用作综合工程情景可接受 | 不称作单因素工期检验。若要识别单个输入影响，需另设只改一项且说明赋权是否冻结的版本。 |
| 第一个 CCUS 的投入、单位现金贡献和折现率 | 条件性计算结构成立；缺乏项目实证校准 | 只能作研究设定演示，不能据此判断项目投资价值。规模兑现子任务未自动连接投资子任务，应说明它们是并列检验。 |
