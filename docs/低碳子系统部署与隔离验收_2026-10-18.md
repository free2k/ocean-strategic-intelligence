共享服务只允许模型请求、来源注册管理及供应商原始内容读取。原站接口附带的文章计数、处理任务和来源健康状态在共享服务内被剥离，不发送给低碳应用。原站文章、规则、研究、推送和采集任务接口均不在代理允许范围内。“同步公众号与 X”“RSS 同步”“重新分类”在低碳版使用自身流水线。

共享来源的新名称、开关和账号信息优先显示，不能被本地旧副本覆盖；篇数、正文状态和同步任务记录只取低碳数据。共享管理页明确说明配置联动，不会把对原站来源配置的授权调整宣称为完全不影响原站。

### 线上隔离

[线上结果](low-carbon-isolation-audit-2026-10-18/deployed/isolation-results.json)包含 23 项检查，均通过：

- 查询实际连接，确认低碳库、端口和角色，原库身份保持原值。
- 原规则指纹与部署前一致；临时修改低碳规则并恢复，原指纹不变。
- 在低碳库提交文章和向量探针，确认原库没有对应记录，再清理低碳探针。
- 两套真实会话分别通过自身正向检查，跨站 Cookie 被拒绝；低碳退出只清理自身 Cookie。
- 共享服务拒绝原文章、规则、数据和原 RSS 同步接口。
- 原环境文件和原 Nginx 站点文件 SHA256 与基线一致。
- 原 knowledge-base 与 ocean-intelligence 的 PID、启动时间保持基线。
- 核对时原 3000 根页面及 3101 健康接口均为 HTTP 200。
- 在低碳应用运行命名空间中验证原环境和原智库数据不可读取。

没有停止原站应用或数据库进行破坏性验证，也没有取消真实共享订阅作为测试。正常调度产生的原站合法数据变化不应被简单当成误写；本次对比保留了原站配置及规则的完整指纹。

## 六 运维与回滚

低碳服务为 low-carbon-app、low-carbon-postgres、low-carbon-shared、low-carbon-backup.timer。发布与备份脚本分别为 [安装工具](../deploy/low-carbon-install.py) 和 [备份工具](../deploy/low-carbon-backup.py)。

应用回滚只切换低碳 release 并更新低碳服务，不运行原站部署或恢复脚本。数据库保留现有数据，不能自动执行删除式降级。需要撤下入口时，只移除低碳站点并在语法检查后平滑重载 Nginx。

原站已有文件和服务仍独立维护。共享订阅配置修改属于双方业务配置变化，不应在回滚低碳版本时自动撤销原站的来源配置。

## 七 实际限制

同机内存、CPU、磁盘、网络和 Nginx，以及共享 AI、订阅配额，仍可能形成间接影响。本次使用低碳服务组资源限制，并验证原站进程和配置保持基线；没有用这些检查替代长期高负载测试。

服务器磁盘剩余约 2.4 GB，整体使用率约 94%，后续扩大原文与研究历史前需要继续安排存储空间。完整人工标注分类集、连续长时间运行、压力负载和跨主机恢复尚未验收，不能宣称分类准确率或所有故障情况下的物理零影响。

实施细节、全部六领域关键词、接口及阶段验收标准见 [开发实施方案](低碳子系统开发实施方案_2026-10-18.md)。修改前的八项耦合复现记录保留为历史证据，不作为新系统未改造的结论。
