**战略量化研判模块：调研评估与升级方案**

调研日期：2026 年 10 月 11 日。评估对象：当前海洋能源战略智能智库的“产业数据洞察”与“战略研究工作台”。

**结论：可行，建议升级。** 现有代码已经具备资料采集、数值证据、官方统计序列、图表与研究问答的基础，适合进一步形成“证据支撑、模型评价、情景比较、持续追踪”的研究流程。主要工作量集中在指标体系、跨来源口径统一和历史版本管理；常规评价模型的计算本身并不复杂。AI 能降低找资料、组织指标、配置模型和解释结果的操作门槛，研究目标、价值取舍与关键假设仍需研究人员负责。

本轮只形成调研与设计方案，不修改应用代码、不部署服务、不修改业务数据。对现有能力的判断来自代码与数据契约检查，尚未对线上全部项目逐项完成指标覆盖率审计。下文的指标、工期和试点范围均为方案建议，不能理解为数据库已经具备全部所需数据。

你提到的“商权法”，本方案按通常所指的“熵权法”理解；“最优解距离法”按 TOPSIS，即“优劣解距离法／逼近理想解排序法”理解。

**一、升级后应回答什么问题**

战略研究没有一套适用于所有问题的统一模型。需要先区分研究问题，再选择方法：

| 研究问题 | 对应能力 | 典型结果 |
|---|---|---|
| 哪些项目、国家或技术路径更值得关注？ | 多指标评价与排序 | 评价得分、排序、优势短板、排序稳定性 |
| 某个项目是否具备实施条件？ | 成熟度评价、约束识别 | 已满足条件、关键缺口、不可被其他优点抵消的约束 |
| 项目过去一年如何演变？ | 同口径纵向追踪 | 原始指标变化、阶段变化、固定基准得分变化 |
| 政策、成本或需求发生变化后会怎样？ | 情景推演与不确定性分析 | 不同假设下的结果范围、排序切换条件 |
| 哪些主体把投入转化为产出的效率较高？ | 效率评价 | 相对效率与改进方向 |
| 有限预算如何配置到多个项目？ | 约束优化 | 满足预算、风险和其他限制的项目组合 |
| 某项政策是否造成了实际效果？ | 因果效果评估 | 有识别条件和局限说明的效果估计 |

“数据提取—数据库—图表—主题—量化研究—演进追踪”的思路成立。主题也可以由研究人员先提出，再反向检查需要哪些数据，避免只能研究已经容易采集的指标。建议两种入口并存：数据发现主题、问题组织数据。

**三、方法调研：按用途组织，而非按模型名称堆叠**

下面覆盖政策研究、产业与能源研究中成熟的决策分析方法，不是各方法使用频率的统计排名。多指标评价的专业性来自研究目标、指标、尺度、权重、检验与解释构成的完整流程。[英国政府多准则分析手册](https://www.gov.uk/government/publications/multi-criteria-analysis-manual-for-making-government-policy)提供了政策选择的系统方法框架。

| 方法 | 主要作用与适用问题 | 必要条件或局限 | 建议位置 |
|---|---|---|---|
| 层次分析法 AHP | 将目标分解为维度、指标，通过成对判断形成权重；适合需要表达战略偏好的评价 | 需要真实的专家判断与一致性检查；指标过多时比较负担明显 | 首期核心；[Saaty 原论文](https://doi.org/10.1504/IJSSCI.2008.017590) |
| 最优最劣法 BWM | 用“最好／最重要”和“最差／最不重要”的参照减少权重判断负担 | 仍需明确评价尺度与人员偏好；不是 AI 自动生成客观权重 | 第二期交互优化；[Rezaei 原论文](https://www.sciencedirect.com/science/article/pii/S0305048314001480) |
| 熵权法 EWM | 根据评价矩阵的信息差异赋权，形成数据侧的区分权重 | 易受异常值、样本与标准化影响；差异大不等于战略重要；常量指标缺少区分信息 | 首期可选；能源研究已有[熵权—TOPSIS 应用](https://www.sciencedirect.com/science/article/pii/S235248472301329X) |
| CRITIC | 利用指标的对比强度与指标间相关关系形成数据权重 | 相关关系估计需要数据支持；不自动决定哪些战略维度应该删除 | 第二期；[原论文](https://doi.org/10.1016/0305-0548(94)00059-H) |
| TOPSIS | 根据与正、负理想解的距离比较对象，适合多指标综合排序 | 得分依赖参照对象、标准化和权重；不是成功概率，也不直接给出预算最优组合 | 首期核心；[TOPSIS 与 VIKOR 比较研究](https://www.sciencedirect.com/science/article/pii/S0377221703000201) |
| 多属性价值评价／加权价值模型 | 以明确的价值函数汇总表现，便于解释指标贡献和取舍 | 不能随意把不同单位数值相加；需明确尺度、补偿关系和权重对应的绩效范围 | 首期解释基线；后续支持摆幅赋权，见[官方 MCDA 指南](https://www.gov.uk/government/publications/green-book-supplementary-guidance-use-of-multi-criteria-decision-analysis/use-of-multi-criteria-decision-analysis-in-options-appraisal-of-economic-cases) |
| 模糊综合评价、模糊 AHP | 表达“较高风险、基本成熟”等带模糊性的专家判断 | 隶属度与等级含义需有规则和依据；不能用模糊模型掩盖完全没有证据的指标 | 第二期；海上能源已有[模糊风险评价研究](https://www.sciencedirect.com/science/article/abs/pii/S0360544221003066)，模糊 AHP 见[Buckley 原论文](https://www.sciencedirect.com/science/article/pii/0165011485900909) |
| VIKOR | 在总体表现与最大短板之间寻找折中方案 | 需要说明折中偏好参数，和 TOPSIS 的目标并不相同 | 专项扩展；同上 TOPSIS／VIKOR 论文 |
| PROMETHEE／ELECTRE | 根据偏好关系、阈值与超越关系比较方案；部分 ELECTRE 配置可表达否决条件 | 设置与解释较复杂；有些结果允许不可比，不能强行给出唯一排行榜 | 高级决策；[PROMETHEE 原论文](https://pubsonline.informs.org/doi/10.1287/mnsc.31.6.647)、上述多准则分析手册 |
| 灰色关联分析 GRA | 比较序列与参考序列的接近程度，辅助识别相似演变 | 参考序列、无量纲化和参数影响结果；关联度不代表因果关系 | 探索性扩展；[邓聚龙原始理论论文](https://uranos.ch/research/references/Julong_1989/10.1.1.678.3477.pdf) |
| 主成分／因子分析 PCA／FA | 分析指标结构、冗余与潜在维度 | 需要合适的样本与结构检验；最大方差方向不必然对应战略重点 | 指标体系诊断；[OECD/JRC 综合指标手册](https://knowledge4policy.ec.europa.eu/sites/default/files/jrc47008_handbook_final.pdf) |
| 数据包络分析 DEA | 比较多个同质主体的投入产出效率 | 需要可比投入、产出和足够样本；投入产出维度过多会削弱区分度 | 有条件的效率专题；[Charnes 等原论文](https://www.sciencedirect.com/science/article/pii/0377221778901388) |
| 网络层次分析 ANP | 处理维度间的依赖与反馈 | 专家判断、建模和解释负担较高；不应只因指标相关就使用 | 有明确依赖结构的专题；[Saaty 专著](https://link.springer.com/book/10.1007/0-387-33987-6) |
| 情景分析＋敏感性分析／蒙特卡洛 | 比较政策、需求、成本等假设变化；有分布依据时模拟不确定性 | 情景是条件假设；没有分布依据时应做范围分析，不伪造概率 | 敏感性首期必备；情景第二期，参考[政府未来研究工具包](https://www.gov.uk/government/publications/futures-toolkit-for-policy-makers-and-analysts/the-futures-toolkit-html)与[Green Book 2026](https://www.gov.uk/government/publications/the-green-book--2/the-green-book-2026) |
| 时间序列模型、系统动力学 | 前者根据时间结构进行预测；后者模拟存量、流量与反馈机制 | 前者需要足够有效历史和回测；后者需要机制、参数与模型校验 | 按专题发展；[NIST 时间序列指南](https://www.itl.nist.gov/div898/handbook/pmc/section4/pmc4.htm)、[系统思维工具包](https://www.gov.uk/government/publications/systems-thinking-for-civil-servants/toolkit) |
| 成本效益／成本效果分析、线性／整数规划 | 评价经济代价和收益；在预算与其他约束下求解配置方案 | 需要成本、收益或效果、约束等专门数据；综合评分不能替代这些输入 | 资源配置专题；经济评价参考上述 Green Book 2026 |
| 面板模型、双重差分等因果评估 | 研究政策或事件对结果的影响 | 需要对照、时间结构及识别条件；新闻增加和得分上升都不足以证明政策有效 | 后期政策效果专题；[Magenta Book 方法附录](https://www.gov.uk/government/publications/the-magenta-book/magenta-book-annex-a-analytical-methods-for-use-within-an-evaluation-html) |

德尔菲法、SWOT、PESTLE、地平线扫描等更适合组织专家意见、发现驱动因素和形成研究主题，本身不自动生成有效的量化评价。可用它们帮助建立指标体系，再接入相应计算方法。[政府未来研究工具包](https://www.gov.uk/government/publications/futures-toolkit-for-policy-makers-and-analysts/the-futures-toolkit-html)将这些方法放在不同的未来研究环节中。

**四、推荐的单模型与组合路线**

| 路线 | 适用情形 | 平台应提供的解释 |
|---|---|---|
| AHP → TOPSIS | 有明确战略目标，指标偏好需要专家表达，且有同口径评价矩阵 | 判断矩阵、一致性、权重、理想解、距离、排序与敏感性 |
| 熵权 → TOPSIS | 同质对象数据较完整，重点比较数据表现差异 | 样本范围、标准化、熵权来源；声明其为数据区分权重 |
| AHP＋熵权／CRITIC → TOPSIS | 同时考虑战略偏好与数据区分能力 | 两套权重、融合方式、融合参数与结果变化 |
| AHP → 模糊综合评价 | 成熟度、政策环境、协同风险等含较多有依据的定性指标 | 每个等级的定义、证据、专家意见与隶属规则 |
| 多属性价值评价＋敏感性分析 | 需要向评委和研究人员清楚说明各指标贡献及取舍 | 价值函数、固定标尺、权重与贡献分解 |
| 评价模型＋情景分析 | 比较不同政策、需求、成本和实施路径假设 | 每个情景改变什么、哪些是真实数据、哪些是假设 |
| 约束筛选 → 评价 → 组合优化 | 项目存在硬性准入条件，且最终需要配置资源 | 先排除不符合条件的方案，再比较与优化，避免其他高分抵消硬约束 |

上述组合是本项目的候选设计，并非任何研究问题的默认最优方法。不同模型结果不一致时，应展示分歧及原因，不把多个排行榜简单平均后称为“科学共识”。

组合赋权可以采用透明的凸组合，例如 `w = α × w_专家 + (1 − α) × w_数据`，但 α 必须有研究目的和人员确认依据，不能默认“各占 50% 就更科学”。敏感性分析应检验不同 α 下结论是否稳定。

专业评价还需要解释指标尺度：容量从 1 增加到 2，与从 100 增加到 101，未必具有相同战略意义。成本可能存在阈值，某些条件可能不可补偿。建议每个指标配置方向、有效范围、价值函数或等级锚点，并在这些定义下讨论权重。摆幅赋权提供了考虑绩效变化范围及其实际价值的思路；简单打分加权不足以覆盖完整的专业决策过程。[官方 MCDA 指南](https://www.gov.uk/government/publications/green-book-supplementary-guidance-use-of-multi-criteria-decision-analysis/use-of-multi-criteria-decision-analysis-in-options-appraisal-of-economic-cases)

**五、建议的研究流程与页面组织**

建议将模块内部的专业研究入口命名为“战略量化研判”。一级导航“产业数据洞察”是否同步更名，可以在整体模块设计确定后再处理。

```mermaid
flowchart LR
  A[全球信息感知] --> B[情报证据与指标事实库]
  B --> C[数据洞察与主题发现]
  C --> D[研究主题与指标体系]
  D --> E[权重和量化评价]
  E --> F[敏感性检验与情景比较]
  F --> G[演进追踪与研究成果]
  G --> D
```

建议在当前模块内逐步形成五个入口，页面默认仍先展示可立即使用的数据概况：

| 入口 | 用户的任务 | 主要内容 |
|---|---|---|
| 数据概况 | 看清有哪些数据、覆盖到什么时间 | 保留现有统计与图表，增加指标覆盖与缺口提示 |
| 主题研究 | 明确研究问题和比较对象 | 主题创建、对象集合、证据集、指标体系与研究范围 |
| 量化评价 | 完成可解释的评价 | 模型推荐、权重配置、校验、结果与依据 |
| 情景推演 | 比较条件变化 | 基准及备选情景、变化范围、关键假设 |
| 演进追踪 | 持续观察主题或项目 | 原始指标、阶段里程碑、固定基准评价、变化原因 |

结果页面建议统一呈现：研究范围与时间、模型与指标版本、指标贡献或距离解释、优势和短板、排序稳定性、数据覆盖与缺口、原文或单元格依据、与上期变化原因。

新闻量、资料覆盖率可用于主题发现和监测关注度，但应与产量、成本、实际减排、项目成熟度分开展示。资料多只能说明当前收录范围中的信息较丰富，不能直接作为产业实力或实施成功率。

**六、数据库需要补齐的研究层**

建议新增派生数据与研究表，通过稳定标识关联原有资料及版本。既有文档、原始文件、采集记录和业务事实继续保留，新增模型结果不覆盖原始数据。

| 新增对象 | 关键字段或规则 |
|---|---|
| 研究主题 | 稳定 ID、研究问题、地域与产业范围、对象集合及版本、起止期、更新频率、负责人 |
| 指标字典 | 指标 ID、定义、对象层级、方向、标准单位、实际／规划／预测性质、频率、适用边界、换算规则 |
| 指标事实 | 项目或主体 ID、指标、统计期、有效日期、原值与原单位、标准值、来源版本、原文或单元格、提取与核验状态 |
| 指标体系版本 | 层级、指标组合、尺度与锚点、硬约束、允许的补偿关系、缺失值规则 |
| 权重与专家意见 | 方法、判断矩阵或其他输入、一致性结果、人员意见及分歧、融合参数 |
| 评价任务与结果 | 输入快照哈希、模型与计算程序版本、参数、对象集合、指标值、权重、得分、排序、检验结果、运行时间 |
| 情景版本 | 改变的变量、假设依据、区间或分布、模拟配置及随机种子 |
| 追踪与里程碑 | 事实生效时间、来源发布时间、平台首次掌握时间、版本链、变化原因 |

跨来源合并时，不能仅凭“指标名字类似”认定可比。必须核对主体和阶段、地域范围、年度能力还是累计能力、实际值还是规划值、统计期、单位、来源版本及口径。例如公布的年封存能力不能与已经实现的封存量视为同一指标；租约有效不能等同项目投产。

缺失值不得默认置零。关键指标缺失时，返回“数据不足，暂不形成完整评价”，保留可展示的分项表现；非关键缺失值的处理方法必须预先定义并披露。约数、上下界和区间应保留其性质，进入区间或情景分析，不能由 AI 转为无依据的精确值。

建议分别展示“评价表现”和“证据质量／覆盖情况”，避免披露少的项目自动被认为表现差，也避免披露充分的项目自动被认为战略价值高。证据冲突需记录来源和采用依据，不简单取平均。

**七、随时间追踪：必须建立可比较的历史**

至少记录三个不同的时间：指标或事件实际对应的时间、来源发布或修订时间、平台首次获取该版本的时间。评价运行时间另行保留。这样才可以区分“当时已经知道什么”和“今天根据现存资料回溯重建了什么”。

建议保留三条相互关联的轨迹：

1. **事实轨迹**：原始容量、成本、产量、进度等指标怎么变。
2. **过程轨迹**：许可、融资、最终投资决策、建设、投运等里程碑何时发生，证据是什么。
3. **评价轨迹**：在相同指标、权重和参照尺度下，成熟度、吸引力或风险怎么变。

跨期最容易出现的错误是每期重新计算最大最小值、熵权和理想解，然后把这些分数连成“进步曲线”。参照集合变化本身可能导致分数变化。综合指标的跨期标准化需要明确参考范围，新增年份也可能引发历史值重算。[OECD/JRC 综合指标手册](https://knowledge4policy.ec.europa.eu/sites/default/files/jrc47008_handbook_final.pdf)

因此，本项目建议：同一期的横向 TOPSIS 排序与固定参照的纵向追踪分开。横向页面显示“本期相对位置”；纵向页面优先显示原始值，并采用冻结的权重、尺度与参照点形成“固定基准评价”。如果对 TOPSIS 使用固定参照改造，应明确标为“固定参照点评价”，说明与每期样本内 TOPSIS 的区别。

修改指标体系或权重后生成新版本，不覆盖旧结果。可以另外提供“按新方法重算历史”的曲线，但应与当时实际产生的评价曲线明确区分。变化解释应分辨事实变化、来源修订、口径变化、模型变化和样本变化。

当前登记快照不能证明过去各期状态。来源未记录的历史保留空缺；只有在原始归档或明确历史材料中找到依据，才补建历史事实。新增采集从此后持续积累版本，历史修订再单独登记。预测值与已观测轨迹分开，不能拼接成同一种实际数据。

**八、AI 人机交互：操作门槛可降低，方法门槛仍需管理**

| 工作 | AI 适合辅助什么 | 研究人员与计算程序负责什么 |
|---|---|---|
| 提出问题 | 将自然语言整理为研究问题、范围与候选对象 | 人确认比较目标与适用边界 |
| 组织证据 | 检索材料、提出指标映射候选、列出缺口与冲突 | 规则与人工核验保证事实和口径 |
| 建立指标体系 | 给出有来源说明的指标建议、发现重复或遗漏 | 人确认战略含义、尺度、阈值与硬约束 |
| 配置权重 | 用通俗语言解释成对比较，提示不一致和分歧 | 专家作出实际判断；程序计算权重与一致性 |
| 执行评价 | 提出适用模型建议和配置草案 | 确定性程序校验输入、计算和归档结果 |
| 解读结果 | 根据计算结果与证据说明优劣、变化和局限 | 禁止凭语言模型补造得分、引用或成功概率 |
| 追踪更新 | 提示新增证据、指标变化与需要复核的口径变化 | 已确认规则下自动生成新评价；重大方法变更再确认 |

用户可以输入：“比较欧洲海上 CCUS 项目的实施成熟度，重点考虑许可、投资决策和基础设施配套，并按季度追踪。”系统先展示范围、对象和指标覆盖，然后给出方法与权重交互，计算后再形成解释与研究记录。

首次建立主题需要做较多领域判断；已确认主题的日常更新可以自动执行。AHP 对同一层的 6 个指标需要 15 次成对比较，8 个指标需要 28 次，故建议首期控制层级规模，采用分层问答、保存判断、默认研究模板；后续可用 BWM 降低交互负担。模板权重必须标明来源与适用场景，不能冒充专家共识。

| 门槛 | 评估 |
|---|---|
| 普通使用者的计算与操作 | 模板成熟后较低，不需要手算或编程 |
| 首次定义研究主题与指标 | 中等，需要理解产业对象和指标意义 |
| 形成严谨、可辩护的结论 | 中高，需要领域人员审查取舍、缺失和不确定性 |
| 平台工程实现 | 中等；主要难点是数据与历史管理、交互和检验 |

AI 降低操作成本，但不能创造缺少的数据、专家共识或因果识别条件。结果解释应引用程序实际输出，并保留版本与核验过程；这也符合分析质量管理对验证和可复核性的要求。[AQuA Book](https://www.gov.uk/guidance/the-aqua-book)

**九、建议试点：海上 CCUS 项目实施成熟度与关键约束**

代码已经包含 CCUS 项目登记与能力解析，以及 Liverpool Bay 的阶段规划示例，适合优先做覆盖审计。建议先选一组有海上适用证据、对象边界清楚、同类且资料足够的项目；项目个数以审计结果决定。容量和登记状态已存在数据入口，许可、融资、合同等字段还需要检查与补充，不能预先认定完整可用。

候选指标体系如下，需与领域人员确认后定稿：

| 维度 | 候选指标与证据 | 注意事项 |
|---|---|---|
| 实施进展 | 最终投资决策、建设、投运里程碑 | 分类阶段不默认等距离，阶段锚点需定义 |
| 许可与合规准备 | 关键许可取得情况、适用范围、有效时间 | 不具备关键许可时可设硬约束，而非让其他高分抵消 |
| 基础设施配套 | 捕集、运输、封存链条各环节及连接情况 | 合作公告不等同已落实的建设或可用能力 |
| 商业落实程度 | 已披露融资、客户或相关合同 | 需区分意向与签约；公开资料不足时保留缺口 |
| 进度兑现情况 | 已有明确计划与实际里程碑的偏差 | 只有存在可追溯基准计划时才计算偏差 |

公布容量作为规模描述单独展示，不直接把“大容量”定义为“高成熟度”。该主题也不直接计算实际减排效果；后者需要实际运行、封存与核算数据。

试点流程为：审核对象与覆盖 → 固定指标和尺度 → AHP 形成研究偏好 → TOPSIS 比较本期对象，并以加权价值结果辅助解释 → 检验权重和关键数据变化 → 固定基准持续追踪 → 生成带证据、版本和局限的研究简报。

若该主题缺口过多，可先采用资料更充足的“同一官方统计口径下的海上油气田运营表现”作为计算试点，再推进 CCUS。不能把国家总产量、公司全船队季度收入与单项目年能力混合比较。

**十、计算与性能实现建议**

现有 Node 服务与 PostgreSQL 适合承担首期的常规指标评价。小规模 AHP、熵权、TOPSIS 不需要 GPU，也不需要把全部数值计算交给大模型。是否需要新增专门计算服务，应由实际数据规模、模拟次数和求解器依赖决定。

建议划分为：指标校验、标准化／价值函数、赋权、评价、敏感性检验、结果归档六个确定性计算步骤。每一步有明确输入输出与版本，AI 通过受约束的参数接口调用这些能力。

结合本网站刚修复的页面响应问题，较重的批量回测、蒙特卡洛或优化任务应进入后台队列／独立工作进程，页面提交后即时返回任务编号，再显示状态与缓存结果；不要在主 HTTP 请求或页面导航中等待长计算。首期先做实际规模基准测试，再决定工作进程数量及硬件需求。

**十一、实施阶段与投入评估**

以下为基于当前代码的工程量粗估，单位为开发人日，不是交付承诺。领域人员确认、来源补齐、第三方接口变化和上线窗口可能改变实际周期。

| 阶段 | 交付内容 | 粗估 |
|---|---|---|
| 0：方法与数据审计 | 定稿一个主题，检查对象覆盖，建立首批指标字典、尺度和缺失规则 | 3—5 人日，另需领域人员参与 |
| 1：可用闭环 | 主题管理、事实映射、AHP／熵权／TOPSIS、加权价值解释、敏感性分析、输入和结果版本、固定基准追踪、一个真实试点 | 15—25 人日 |
| 2：交互与不确定性 | BWM、CRITIC、模糊评价、情景管理、变化归因、研究报告联动 | 10—20 人日，按需求取舍 |
| 3：专题方法 | DEA、预测、因果评估、系统动力学或资源优化中的具体专题 | 每类单独估算；复杂专题可能超过 20 人日 |

首期不应同时铺开所有模型和全部产业主题。先完成一套从真实证据到可复算结果的流程，数据覆盖合格后扩展同类主题。比赛展示可以围绕一个真实主题演示“发现—证据—评价—检验—演进”，其说服力来自问题与结论可验证。

**十二、首期验收标准**

1. 一个真实主题形成有依据的可比对象与指标矩阵；每个输入可定位到原文或工作簿单元格。
2. 指标方向、单位、性质、统计期、尺度、对象范围和缺失规则能逐项检查；冲突与不可比数据不悄悄进入计算。
3. 模型与公开可核对算例一致；处理常量指标、零值、负值、成本型指标、并列和退化矩阵等边界，不能出现无意义数值或虚假排序。
4. AHP 权重有真实判断输入和一致性检查；熵权结果明确说明其含义；同一输入与版本可复算一致。
5. 结果提供权重及关键输入的敏感性检验；不稳定排序明确呈现，不能只展示唯一第一名。
6. 历史评价保留原版本；固定基准下的变化可解释，来源修订与模型改变分别记录。
7. 时间回溯避免使用当时尚未掌握的数据；回溯重建与当时产生的评价清楚区分。
8. 分析任务运行时主要导航和现有查询保持可用；对模拟与批量任务检验后台执行和缓存行为。
9. 上线采用新增研究层与独立结果存储，升级前后核对已有数据，保留程序回滚路径。

**建议决策**：批准“战略量化研判”的升级方向，先做一个主题的数据与方法审计，再实现 AHP、熵权、TOPSIS、透明的价值评价、敏感性检验及版本追踪。后续方法根据研究问题和数据条件启用。最大的收益是把目前的资料与图表，转化为有对象、有指标、有取舍、有证据且能够持续复核的战略研究成果。
