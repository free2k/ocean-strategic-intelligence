# 低碳子系统开发实施方案

| 项目 | 当前约定 |
| --- | --- |
| 版本 | 1.2，依据后续实施授权更新 |
| 日期 | 2026年10月18日 |
| 产品名称 | 碳索智研，低碳情报与决策支持平台 |
| 部署目标 | 阿里云 39.96.24.170，本地开发后直接发布，禁止 Git push |
| 原则 | 代码可复用；文章、规则、向量、任务、研究成果和会话隔离 |
| 用户明确允许的共享 | AI 模型服务、公众号及 X 订阅集合、RSS 订阅配置 |

本版按“共享代码和指定服务，独立保存业务数据”实施。低碳版不复制原站文章库、向量库、研究成果或任务记录，不以同表的 system_id 筛选实现隔离。它拥有独立 PostgreSQL 实例及完整业务表，并在业务初始化之前核验数据库、目录和实例身份。

用户后续明确允许 AI 与订阅源共享：从任一系统新增、取消或调整共享订阅，会影响另一系统的来源配置。两套系统分别抓取供应商原始内容，按各自规则清洗、分类和入库。低碳版“立即采集”只启动自身任务。

同机部署仍共享操作系统、资源、Nginx 入口和外部服务额度。应用数据隔离不等于物理资源完全隔离；“任何情况下绝无影响”不作为可证明结论。前版独立主机、独立供应商及独立模型额度方案保存在 [v1.1 历史方案](low-carbon-isolation-audit-2026-10-18/implementation-plan-v1.1.md)，由本版约定取代。

## 一 业务范围

保留现有“信息感知、证据沉淀、变化监测、国别态势、数据洞察、量化研究”的流程，统一为低碳业务口径，覆盖陆上与海上场景。分类不再要求必须出现海洋能源语境。

首版提供六领域规则及 AI 复核、独立采集与审计、逐字引用校验、独立研究模板和成果保存、共享来源管理、独立登录与运维入口。方法库中的现有执行引擎继续复用，未实现的方法仍保留其能力限制，不通过更名宣称已具备工程核算、认证碳核查或工业实时控制能力。

- 边界：泛宏观经济、普通金融和无气候内容的 ESG 宣传不纳入；以技术项目为主归相应技术领域。

### 通用判定

中文包含匹配，英文忽略大小写并检查词边界；组合规则要求同段成立，不跨文章拼接语境。保留主领域及辅助领域，主领域优先依据标题和正文主旨。主体为招聘、招生及促销的信息予以排除。

规则未确定的有正文记录可进入 AI 语义复核。AI 必须选取提供的原文片段编号，不能以模型置信度替代证据。结构化提取继续校验引文确实存在于原文，不从实体共现推断合作，不把设计能力或计划量当实际减排量。人工分类优先保留。

规则草稿、已应用版本、语义缓存、正文版本与提取结果全部写入低碳库。更新草稿不改写已发布研究；重新处理产生本系统的新版本。

低碳新实例中建立完整的 `public.articles/sources/filter_rules/article_chunks`、`classification.*`、`mp2rss.*`、`ocean_intel.*` 和 `ocean_research.*`。保留兼容 schema 名仅为复用代码；这些表位于不同 PostgreSQL 实例，数据库里不存在跨库视图、外部表、逻辑复制或原站连接。

启动前同时核验三个 DSN 指向本机低碳端口、库名和角色，并查询实际实例身份。文件根目录固定为 `/opt/low-carbon/data`，核验真实路径、实例标记与三个子目录，拒绝路径替换和符号链接逃逸。检查位于 `Store.init()` 之前，普通启动及显式初始化均执行。

应用以低碳 Unix 用户运行，systemd 设置只读系统目录、低碳限定写目录、原站环境和数据目录不可访问、内存与 CPU 限额。共享依赖目录只读复用，原站 release 不被修改，发布不执行原恢复脚本或 `restart all`。

## 五 共享接口边界

新增仅监听回环地址的 `low-carbon-shared` 服务，端口 3270。它使用独立令牌认证，读取原站配置中经允许的模型和订阅凭据。低碳应用只持有共享服务令牌，不能获得原站登录签名密钥或供应商密钥。

| 接口 | 所属与行为 |
| --- | --- |
| /api/filters/** | 低碳自身数据库；禁止共享代理 |
| /api/data、document、classification-audit | 低碳自身数据 |
| /api/collection、process、processing-runs | 低碳自身任务与锁 |
| /api/strategy、research、period-reports、uploads | 低碳自身文件及研究数据库 |
| /api/subscriptions GET | 读取共享注册配置；计数、正文状态、任务记录换为低碳自身统计 |
| /api/subscriptions/action | subscribe、unsubscribe、update、refresh 通过共享服务；sync 在低碳版截获 |
| /api/rss/sources GET POST PATCH DELETE | 共享 RSS 注册配置；采集篇数使用低碳自身统计 |
| /api/rss/sync | 只启动低碳采集，不代理原站同步 |
| /provider/open-api/... | 只读供应商原始订阅与文章接口，不读取原站文章库 |
| /v1/chat/completions、embeddings | 使用原站模型配置转发，结果由低碳版独立保存 |
| /api/system | 返回本系统身份、分类版本、隔离与共享范围 |

共享服务不开放原站 `/api/articles`、规则、推送、研究成果或同步任务接口，不存在获取资料失败后回退原站文章库的路径。来源管理的可用性依赖共享服务；已经入库的资料、分类、研究回放仍在低碳系统自身。

模型共享意味着预算、并发和供应商故障属于共同依赖。低碳自动采集采用有限 AI 批次，优先处理已明确相关的文章；失败时保留规则候选与失败状态，不把失败标作模型成功。

## 六 采集与成果形成

1. 读取共享来源注册表，更新本地来源状态副本。共享读取失败时保留最后已知配置，记录失败，不能把接口故障当作用户取消全部订阅。
2. 从供应商原始 API、RSS 及低碳基准公开来源独立抓取，不读取原站文章接口或数据库。
3. 保存原文、来源、发布时间、内容哈希和历史版本。缺失发布日期保留未知，不以抓取日期冒充。
4. 按低碳规则与 AI 复核分类，未纳入文章保留审计记录。
5. 对纳入资料生成有原文依据的实体、事件、关系和指标，向量仅写入低碳库。正文或分类变化时清除过时向量。
6. 保存新快照及研究发布版本，保留人工校准和既有成果。失败来源、缺失数据和规则候选分别呈现。

默认每六小时巡检，订阅采用轮转批次、RSS 每源小批读取，避免一次性全库回灌和挤占共享服务。接口返回轮转游标、任务步骤和失败状态。可手动触发低碳采集或处理，任务互斥锁仅属于低碳系统。

公开基准来源用于建立低碳初始资料，包括 Northern Lights 项目业主、IEA、生态环境部、国家发展改革委及工信部相关页面。访问失败按实际记录，不能为凑齐六领域文章而虚构材料。公开基准资料与用户可编辑的共享订阅配置分开展示。

### 隔离验收清单

| 编号 | 验收内容 | 证据与边界 |
| --- | --- | --- |
| ISO01 | 数据库实例、库名、角色与身份一致 | 实际连接查询，不只检查环境字符串 |
| ISO02 | 错误库、端口、角色、实例或目录拒绝启动 | 在 Store.init 前失败 |
| ISO03 | 低碳规则修改不改原规则 | 临时修改低碳草稿并恢复，对比原规则指纹 |
| ISO04 | 低碳文章与向量写入不进入原库 | 独立事务探针和原库只读核对 |
| ISO05 | 共享订阅符合用户授权 | 相同注册集合、接口允许列表；生产不取消真实订阅做破坏性验证 |
| ISO06 | 文件与权限隔离 | 原 .env、数据、锁不可由低碳用户写入；验证真实目录 |
| ISO07 | API 分流正确 | 仅允许 AI 与来源注册共享，文章、规则、研究不代理 |
| ISO08 | 会话与存储隔离 | 原 Cookie 在低碳版无效，低碳 Cookie 在原站无效，退出不清原 Cookie |
| ISO09 | 独立任务与锁 | 仅争用低碳锁，重启恢复自身任务 |
| ISO10 | 共享故障如实降级 | 共享配置不可用时保留本地数据并报告失败；不承诺共享服务故障无影响 |
| ISO11 | 低碳重启不重启原站 | 原站 PID、启动时间与健康状态对比 |
| ISO12 | 备份与回滚限于低碳 | 独立备份、校验和、恢复验证及低碳服务清单 |
| ISO13 | 同机入口边界 | 新站点文件，原站 Nginx 配置指纹不变；仅语法检查后平滑 reload |
| ISO14 | 共享资源声明及限额 | 同机、AI 与订阅额度有共同依赖，记录 systemd 资源限制 |

不将修改前 v1.1 的独立主机、独立供应商测试误标为当前方案通过。长时间运行、完整标注集的准确率和压力负载影响需保留独立测量结果；不能用少量边界样例代替统计评估，也不能把没有执行的故障演练写成完成。

### 功能验收

- 首页、信息感知、证据中心、项目监测、态势、数据洞察、研究工作台及共享管理页可访问，无未捕获浏览器异常。
- 六领域名称与 ID 一致，英文词边界、同段组合、主体排除、停用规则及陆上场景验证通过。
- 模型与规则结果明确区分；引用原文逐字可核对，计划量、设计能力、实际量及研究假设分别保存。
- 量化方法校验输入，产生可复现结果，保存与导出仅访问低碳成果。
- 未登录请求、错误 ID、任务冲突、来源或模型不可用返回本系统状态，不返回原站数据。

## 八 部署与回滚

部署工具为 [low-carbon-install.py](../deploy/low-carbon-install.py)。部署包包含共享运行代码和低碳配置定义，排除原站 .env、node_modules 内容、业务数据、演示交付物和本地凭据。依赖只读复用服务器既有目录，避免在剩余约 2.5 GB 的磁盘上重新安装整套 Nuxt 依赖。

低碳站采用独立 Host。8081 外网访问不通时，使用 Nginx 新增低碳虚拟站点，经 `nginx -t` 后平滑重载；不修改原站代理文件，不重启原应用或原数据库。发布后核对原站进程、配置指纹、规则及健康接口。

低碳备份仅包含新实例与自身文件，保存在专属目录，标注时间与校验和。恢复先在低碳独立临时库验证，再决定是否切换。应用回滚只调整低碳 release、低碳服务及其站点，不执行旧部署脚本或数据库降级删除，不把低碳入口回退代理到原站。

源码留在本地 `codex/low-carbon-subsystem` 分支，不执行 Git push。访问密码、数据库密码、签名密钥和共享令牌均在服务器单独生成，避免将 SSH 密码复用为站点密码或写入仓库。
